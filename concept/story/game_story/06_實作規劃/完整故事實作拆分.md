# 完整故事實作拆分

## 文件定位

本文件把[[03_故事/完整主線—無名之火]]拆成可排程的 Godot 工作。所有路徑、class 與 schema 都是建議方案，尚未實作；正式開工時仍須先建立失敗測試並依專案治理文件確認 authoritative ownership。

## 目前可沿用的專案能力

| 現有能力 | 目前狀態 | 可沿用方式 | 缺口 |
|---|---|---|---|
| `Game` map／UI orchestration | 已實作 | 載入 Town、戰區、HUD 與 modal | 不應再塞入大量章節條件與台詞 |
| `DialogueUI` | 已實作基礎 UI | speaker、文字、選項、advance signals | 沒有資料驅動 runner、逐句隊列、portrait 資產與條件分支 |
| `portal.gd` | 已實作 | target、lock、reason、entered signal | 沒有 story requirement、動態目的地與章節視覺狀態 |
| Battle Portal Hub | 已實作四區入口與中央 Boss anchor | 後期解鎖地獄／天堂／最終入口 | 中央 Boss Portal 尚未建立 |
| `AutumnGuardian` | 已實作三階段範例 | phase signal、telegraph、pattern profile | 無通用 encounter controller、checkpoint 與特殊勝利條件 |
| Boss HUD | 已實作 | 顯示名稱與 HP | 缺怨蝕、自由火種、目標提示與多核心狀態 |
| `MetaState` schema 7 | 已實作 | 保存 persistent progression | 僅有通用 `boss_defeated`，沒有 chapter／choice／memory flags |
| `SaveService` | 已實作 | migration、temp、validation、backup | 新 story schema 需要 migration 與 round-trip tests |

## 建議 ownership

```text
Game
├── MapRoot
├── StoryDirector                 persistent runtime story owner
│   ├── DialogueRunner
│   └── SequenceRunner
├── HUDLayer
├── MenuLayer
└── CardEffectRunner

BossMap
├── BossEncounterController       encounter state/checkpoint owner
├── Boss                          attack and phase behavior
├── ArenaMechanics                anchors/hazards/soul objects
├── StorySequencePlayer           scene-local authored presentation
└── Player
```

- `Game` 只建立與連接，不持有逐章分支邏輯。
- `StoryDirector` 擁有目前 chapter、sequence queue、story flags projection 與演出鎖定。
- `MetaState.story_state` 擁有持久章節狀態；runtime temporary flags 不寫入 Meta。
- Boss script 不直接操作 HUD、save、DialogueUI 或 map transition。
- Scene-specific `AnimationPlayer` 擁有鏡頭、角色移動與燈光時間軸。

## 資料契約

### `data/story/chapters.json`

每章至少包含：

```json
{
  "id": "mid_false_history",
  "order": 5,
  "title": "正史改寫",
  "entry_requirements": ["act1_truth_revealed"],
  "entry_sequence": "false_history_arrival",
  "maps": ["town_false_history"],
  "completion_requirements": ["five_false_memories_seen"],
  "completion_flags": ["false_history_rejected"]
}
```

### `data/story/dialogues/*.json`

- `id`、speaker、text、portrait state、voice cue。
- conditions、choices、next、set_flags。
- 不允許任意 method name 或腳本字串執行。
- localized text 最終拆入翻譯表，JSON 保存 stable text key。

### `data/story/sequences/*.tres`

- sequence ID、scene path、AnimationPlayer animation name。
- input mode、skip target、completion flags、checkpoint policy。
- 不把 NodePath 寫在跨場景 JSON；Scene-local resource 持有 editor-authored NodePath。

### `MetaState.story_state`

建議 schema：

```text
chapter_id
completed_chapters[]
story_flags{}
memory_fragments[]
defeated_story_bosses[]
town_story_state
ending_state
```

- 需要 schema 8 migration。
- flags 採 stable snake_case ID。
- 不保存正在播放到第幾秒；只保存 sequence 前／後 checkpoint。

## 新增核心系統

### StoryDirector

- 驗證章節進入條件。
- 排入 scene-local sequence。
- 鎖定／恢復玩家輸入。
- 開啟 DialogueRunner。
- 完成時原子寫入 flags，再要求 SaveService 保存。
- Map reload 後依 story state 套用 Town 版本與 NPC 狀態。

### DialogueRunner

- 從 catalog 讀取 dialogue graph。
- 逐句投影到既有 DialogueUI。
- 管理 advance、choice、conditional branch 與 completion。
- 支援 world-space battle bark，不在戰鬥中打開 modal。
- 驗證缺失 speaker、next node、循環與非法 flag。

### StorySequencePlayer

- 包裝 AnimationPlayer，不重新發明動畫時間軸。
- 接受 skip、pause、finish signal。
- Skip 呼叫 scene-authored `apply_final_state()`，不可單純 seek 到結尾。
- 支援 camera target、letterbox、NPC movement、audio cue 與 dialogue marker。

### BossEncounterController

- phase state machine、checkpoint、arena reset、HUD projection。
- 支援 HP threshold、mechanic completion 與 narrative choice 三種轉階條件。
- Boss defeat 只發 signal；StoryDirector 決定旗標與下一段演出。
- 重試重建 encounter-owned children，不重新載入整個 Game。

## Scene 與內容拆分

### Town 五種版本

| Scene／狀態 | 用途 | 建議方式 |
|---|---|---|
| Normal | 前篇日常 | 目前 Town authoritative scene |
| FalseHistory | 正史滲入 | Town scene 的 story overlay，不複製完整地圖 |
| Fractured | 多重歷史撕裂 | 專用中期 Scene；碰撞與危險需 editor-authored |
| Ruined | 中後篇廢墟 | 獨立 authoritative ruined scene 或明確 composition resource |
| Rebuilding | 結局 | Ruined scene 上的 progression overlays |

不得用大量 runtime `new()` 重建靜態 Town。重大狀態採 editor-authored scene／overlay，確保視覺檢查與碰撞可驗證。

## 章節製作里程碑

### M0：故事基礎系統

- [ ] StoryDirector、DialogueRunner、SequencePlayer。
- [ ] story catalogs 與 validation。
- [ ] MetaState schema 8 與 migration。
- [ ] 可跳過、可重播、checkpoint-safe 的最小演出。
- [ ] DialogueUI portrait、逐句、choice focus 與多解析度檢查。

驗收：一段 Town 對話可依 flag 分支、保存、重開遊戲後正確延續，skip 與完整播放得到相同最終狀態。

### M1：前篇垂直切片

- [ ] 無名旅人醒來與進城。
- [ ] 鐵匠鋪取得、第一次劍魂對話。
- [ ] 五名 NPC 各一個可操作日常事件。
- [ ] 一座傳送門遠征與一名認不出主角的 Boss。
- [ ] 一段矛盾戰爭記憶回看。

驗收：玩家能從遊戲內理解主角沒有過去、能聽劍魂，並對至少三名居民形成可辨識關係。

### M2：中篇正史改寫

- [ ] FalseHistory Town overlay 與調查物件。
- [ ] NPC 記憶逐步替換。
- [ ] 正史英雄 encounter。
- [ ] 五個真實小事記憶錨點。
- [ ] Fractured Town 逃生與 Ruined Town transition。
- [ ] 廢墟談話與反攻決斷。

驗收：不依賴旁白，玩家能說明正史為何誘人、正史英雄為何危險，以及居民為何選擇真正主角。

### M3：地獄篇

- [ ] 被捨棄人生的五個可探索房間。
- [ ] 地界旁系王室真相。
- [ ] 地獄王四階段 encounter。
- [ ] 怨蝕值、亡魂錨點、SoulCluster、罪簿。
- [ ] 釋放亡魂與摧毀罪簿演出。

驗收：不永久破壞玩家 build；每階段機制可從 telegraph 學會；劇情與戰鬥都表達「放下不屬於自己的復仇」。

### M4：天堂篇與結局

- [ ] 完美 Town 可操作幻境。
- [ ] 天堂王四階段 encounter。
- [ ] 天律、FutureAnchor、自由火種、唯一正確世界。
- [ ] 希望散播 montage。
- [ ] 普通人鍛造尾聲與 ending save。

驗收：玩家必須親手拒絕完美未來；結局後主角失去劇情神力但正常遊戲資料不損毀。

- [ ] `SoulCluster` family projection，不直接修改 catalog。
- [ ] `SoulAnchor` release state 與 interrupted hold。
- [ ] encounter reset 清除臨時卡與 meter。

### Presentation

- [ ] 亡魂臉／姓名恢復演出。
- [ ] 王座融合與罪簿頁面。
- [ ] 遺言字幕排程與音訊 ducking。

### Tests

- [ ] 每 phase 至少一個新空間問題，不只增傷。
- [ ] 怨蝕 100 有 8 秒恢復路徑。
- [ ] 任一合法 build 都能完成 release。
- [ ] 重試不保留臨時 debuff。
- [ ] 正式 flags 僅在 victory 後保存。

- [ ] FutureAnchor 僅快照 encounter data。
- [ ] 回捲安全位置驗證。
- [ ] FreeWillSpark 無死鎖生成。
- [ ] PerfectTownMemory 調查與 optional completion。

### Presentation

- [ ] 敕令文字、圖示、場地幾何同步。
- [ ] 預測路徑與真正 hit area 分層。
- [ ] 完美 Town 與傷痕恢復的無接縫轉換。
- [ ] 天堂王融入背景但核心仍有清楚 hurtbox。

### Tests

- [ ] 所有 edict 都有遵守與違反兩條可行路徑。
- [ ] 回捲不恢復已摧毀 anchor。
- [ ] 回捲不把玩家放進 active hazard。
- [ ] 每循環必定可取得至少一顆火種。
- [ ] 幻境接受選項不污染 canon save。

## 動畫與美術生產細項

- [ ] 先用灰盒 Scene、Polygon2D telegraph 與 placeholder portrait 驗證節奏。
- [ ] 演出定稿後建立 storyboard／animatic。
- [ ] 每個鏡頭列出角色、背景層、VFX、字幕、安全框與音訊 cue。
- [ ] Town 五狀態使用同一座標與 collision contract。
- [ ] 生成 raster art 時依治理要求進行獨立 full-frame、原生物件與 3×2 六切片 review。
- [ ] 最終視覺修改後重做完整視覺 review，再跑結構測試。

## 測試矩陣

| 類型 | 必要覆蓋 |
|---|---|
| Catalog | duplicate ID、missing next、invalid flag、missing scene/resource |
| Story state | chapter gate、idempotent completion、schema migration、round trip |
| Sequence | complete／skip parity、reload recovery、input restore、pause restore |
| Dialogue | choice routing、conditional node、focus、cancel policy、localization key |
| Scene | authoritative paths、NodePath、owner、collision、portal target |
| Boss | phase order、mechanic gates、telegraph/damage match、reset、victory flag |
| UI | 1280×720、1600×900、1920×1080、2560×1440、wide、narrow |
| Smoke | editor parse、main launch、chapter entry、Boss retry、ending return |

## 風險與控制

| 風險 | 控制方式 |
|---|---|
| Game script 繼續膨脹 | StoryDirector／BossEncounterController 明確 ownership |
| 分支旗標爆炸 | 只保存影響可觀察狀態的 stable flags；對話小分支 session-local |
| 過場 skip 破壞狀態 | 每段 sequence 實作 final-state applicator 與 parity test |
| Boss 規則看不懂 | 每機制先單獨教學，再組合；文字＋圖示＋場地三重 telegraph |
| 時間回捲難以正確 | 只快照 encounter-owned data，不序列化整棵樹 |
| 永久削弱破壞 build | 劇情失去的是獨立惡鬼能力，不刪卡牌與裝備 |
| Town 五版本失控 | 共用座標 contract；用 authored overlays／獨立 scene，不散落 runtime patch |

## 建議製作順序

1. 先完成 M0 與一段 3 分鐘故事垂直切片。
2. 以正史英雄戰驗證「記憶錨點影響 Boss」是否好玩。
3. 只做地獄王第一、二階段 prototype，確認釋放亡魂不是站樁負擔。
4. 只做天堂王敕令與 FutureAnchor prototype，確認限制規則仍公平。
5. 機制通過後才大量製作 Town 狀態、角色動畫與完整對話。
6. 最後整合後篇兩王、希望散播與尾聲。

## 完成定義

- 故事能從新遊戲一路進行到普通人鍛造尾聲。
- 每章有可保存、可重入、可跳過的確定狀態。
- 所有重要敘事資訊至少有一個遊戲內可觀察證據。
- 地獄王與天堂王的核心論點同時存在於劇情、機制與演出。
- 所有 focused tests、full regression、editor smoke、main smoke 與 UI 多解析度驗證通過。
- 可見資產完成最終獨立視覺 review。
